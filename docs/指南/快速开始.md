# 快速开始

这是一个**示例文档**，用来验证工具本身能正常工作。把这里的文件换成你自己的 Markdown 就行 —— 工具只读取、不修改。

## 1. 四种打开方式

| 方式 | 命令 | 适用场景 |
| --- | --- | --- |
| 双击打开 | 双击 `md-viewer.html` | 日常阅读，可离线，零依赖 |
| 实时模式 | `node build-docs.mjs --serve` | 边写边看，改完刷新即可（只有本机能访问） |
| 分给同事看 | `node build-docs.mjs --serve --lan` | 同一局域网内的人直接打开你的地址就能看 |
| 只看别的目录 | `node build-docs.mjs --serve <目录>` | 不想把文档搬进本工程 |

双击模式读取页面里内置的数据副本，所以文档有变动后要跑一次 `node build-docs.mjs`；
实时模式每次都重新扫描目录，新增文档刷新页面就会出现。

`--serve` 全程不写任何文件（页面在内存里现生成），所以它指向哪个目录，都不会改动工程里的
`md-viewer.html` / `docs-index.json` / `index.html` —— 这三个产物只由 `node build-docs.mjs` 写出。

服务默认只绑 `127.0.0.1`（只有本机能打开）。加 `--lan` 会绑到本机所有网卡，
启动信息里会列出 `局域网访问：http://<你的IP>:<端口>/`，把那一行发给同事即可；
只想绑某一个地址就用 `--host <你的IP>`。服务没有鉴权，只建议在可信内网里这么用。

## 2. 目录与本工具的关系

```
markdown-docs-helper/
├─ md-viewer.html      ← 双击这个
├─ assets/             ← 页面的样式与应用逻辑（viewer.css / md-core.js / md-app.js…）
├─ build-docs.mjs      ← 构建 / 本地服务
├─ config.json         ← 你主要改这个
├─ docs/               ← 默认被浏览的文档（可以整个换掉）
└─ test/               ← 回归与调试脚本
```

页面本体只留结构、内置文档数据与内联的引擎（导图 markmap、图表 mermaid）；样式和逻辑都外链到
`assets/` 下的文件，改完刷新页面即生效。把页面单独拷走时要连 `assets/` 一起带上
（离线版还需要 `vendor/`，实时版按外链读 `vendor/`）。

文档里可以放心写 Mermaid：`.mermaid` 文件（`mindmap` 版式）会渲染成可缩放导图，
Markdown 正文里的 mermaid 围栏会渲染成图（`stateDiagram-v2`、`flowchart`、`sequenceDiagram`…），
都离线可用、不用装插件。想看各种版式的例子，打开 `docs/示例/Mermaid 图表.md`。

`docs/` 只是默认值。把目录写在命令后面（位置参数）就能指向任何目录，页面里的路径前缀仍然是 `docs/`，
所以 `config.json` 里的 `folders` / `exclude` / `docs` 都不用跟着改。
目录最多写一个；写错了（未知参数、不存在的目录…）脚本会直接报错，不会拿默认目录凑合。

## 3. 只读保证

- 构建脚本只读文档目录，写入被限制在工程内，且**明确禁止写进文档目录**；
- 页面本身没有任何写文件的能力，搜索、过滤、隐藏文档都只作用于显示层。

> 换句话说：放心把这个工具指向你正在写的文档目录，它不会动你的文件。
