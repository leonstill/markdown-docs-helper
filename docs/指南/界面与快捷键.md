# 界面与快捷键

本页讲页面长什么样、每个按钮做什么、键鼠怎么操作。

页面本身有两个形态，**界面完全一致**（都由 `build-docs.mjs` 从 `page.template.html` 生成），
差别只在数据来源与刷新方式：

| 打开方式 | 页面 | 数据来源 | 改了文档 / 配置之后 |
| --- | --- | --- | --- |
| `node build-docs.mjs --serve` 实时模式（`http://127.0.0.1:8899/`，加 `--lan` 可给局域网内其它机器看） | `index.html` | 直接读文档目录下的文档与 `config.json` | **刷新页面即可**，新增文档也不用重建 |
| 双击 `md-viewer.html`（`file://`） | `md-viewer.html` | 页面内置的文档（`.md` + `.mermaid`）与配置副本 | 跑一次 `node build-docs.mjs`，再刷新页面 |

只有 `node build-docs.mjs` 这条构建命令会写文件（一次写出 `md-viewer.html`、`docs-index.json`、`index.html`）；
`--serve` 与 `--check` 都不写文件 —— `--serve` 的实时版页面在内存里现生成，
所以 `--serve <别的目录>` 不会把仓库里那份离线版产物顶掉。

两个页面只有两处不同：实时版把四个引擎（markmap 导图、mermaid 图表）换成本地外链
`<script src="vendor/markmap/*.js">` / `<script src="vendor/mermaid/mermaid.min.js">`（浏览器可缓存），
并把内置快照置空（实时模式每次刷新都去读 `docs-index.json`，留一份旧副本只会误导）。
离线版则把引擎整段内联进页面（其中 mermaid 有 3 MB，只在文档里真的用到了图表时才内联）。

## 三栏布局

- **左侧目录栏**：全部文档，可搜索、可分组；显示哪些文档由 `config.json` 决定
  （全文搜索的结果页会把它临时换成「命中文件导航」）
- **中间正文**：Markdown 渲染结果，表格可横向滚动，代码块带边框
- **右侧目录栏**：当前文档的标题大纲，滚动时自动高亮所在章节

两侧栏都可以独立隐藏，并且记住上次的开关状态。

正文的宽窄不用改配置：鼠标移到正文**左或右边缘**（约 21px 宽的感应区，竖线就在它正中）会显出一条竖线，
按住往外拖就对称变宽、往里拖就对称变窄，松手记住；拖动时**另一侧的竖线同时亮起**，两条线之间就是当下正文的宽度；
双击那条边回到 `config.json` 的 `reading.maxWidth`。细节见下文「正文宽度的实现要点」。

## 工具栏

顶栏功能按钮一律**只有图标、没有文字**（图标是内联 SVG，颜色跟随 `currentColor`；品牌区是那枚带标题的按钮，唯一的例外），
文字说明放在悬停提示和无障碍标签里（`title` / `aria-label`），所以鼠标停上去仍能看到它是干什么的。

| 按钮（图标） | 位置 | 作用 |
| --- | --- | --- |
| 侧栏开关（左栏高亮） | 最左 | 开关左侧目录栏（快捷键 `[`） |
| 品牌区（图标 + 标题） | 左栏开关右侧 | 弹出下拉菜单：**帮助** / **关于…**（图标 + 标题 + 副标题整块都是热区；再点一次、点别处或按 `Esc` 收起） |
| ‹ / › | 右半区 | 上一篇 / 下一篇，按左栏顺序切文档 |
| 放大镜 | 右半区，打印左侧 | 从顶栏下方滑出**全文搜索条**并聚焦输入框（再点一次收起，见下文「全文搜索」） |
| 打印机 | 右半区 | 打印 / 导出 PDF（等价于 `Ctrl+P`） |
| 链条 | 右半区 | 复制当前文档链接（带文档与章节位置）；复制成功后图标短暂变成对勾 |
| 太阳 / 月亮 | 右半区 | 切换配色，跟随系统偏好并记住选择（浅色时显示月亮、深色时显示太阳，表示「点一下会变成什么」） |
| 侧栏开关（右栏高亮） | 最右 | 开关右侧目录栏（快捷键 `]`） |

## 页面操作

| 操作 | 方式 |
| --- | --- |
| 开关左侧目录栏 | 工具栏最左侧按钮，或快捷键 `[`，或左栏右上角 `✕` |
| 开关右侧目录栏 | 工具栏最右侧按钮，或快捷键 `]`，或右栏右上角 `✕` |
| 调整正文宽度 | 按住正文左 / 右边缘那条竖线拖动（向外拖对称变宽，两边同时走），双击那条边复原 |
| 搜索（左栏目录内） | 左栏搜索框，按标题与正文匹配并显示「N 处」和摘要片段，`/` 聚焦、`Esc` 清空 |
| 全文搜索（结果开在正文区） | 点顶栏放大镜滑出搜索条 → 输入 → 回车或点右侧放大镜，详见下文「全文搜索」 |
| 在结果页里跳到某一篇 | 点左栏「命中文件导航」里的文件项（视口移到那一组，不改地址栏） |
| 打开文档 | 点左栏条目、点首页卡片，或直接点正文里 `docs/xxx.md` 形式的引用 |
| 跳转章节 | 点正文里的 `§5.3` 这类引用，或点右栏目录 |
| 跨文档跳转 | 正文里 `` `docs/指南/快速开始.md` `` 形式的行内代码（写法见根目录 `README.md` 的「跨文档章节引用」） |
| 上一篇 / 下一篇 | 顶栏 ‹ › 两个图标（顺序与左栏一致） |
| 切换深 / 浅色 | 顶栏太阳 / 月亮图标（跟随系统偏好，且记住选择） |
| 打印 / 导出 PDF | 顶栏打印机图标，或 `Ctrl+P` → 目标选「另存为 PDF」 |
| 复制当前文档链接 | 顶栏链条图标（链接带文档与章节位置，可直接发给别人） |
| 看帮助 / 看版本 | 点顶栏品牌区 → 菜单里选「帮助」或「关于…」；对话框可以用 `Esc`、右上角 `✕`、底部「关闭」或点框外空白关掉 |
| 导图 / 图表全页面显示 | 导图或图表工具栏的「全屏」按钮（见下文「思维导图操作」「嵌入的 Mermaid 图表」） |

侧栏的开关状态会记住（默认开启记忆，可在 `config.json` 的 `sidebar.remember` / `toc.remember` 里关掉）。
拖出来的正文宽度同样记在本地（`localStorage` 的 `mdv-content-w`），**记住的是这个本地值**：拖过之后 `reading.maxWidth`
就只当默认值用（双击复原时回到它），改它要看得见效果得先双击复原、或换一台机器 / 清掉本地记录。

## 快捷键

| 按键 | 作用 |
| --- | --- |
| `[` | 开关左侧目录栏 |
| `]` | 开关右侧目录栏 |
| `/` | 聚焦**左栏**搜索框（顶栏搜索条请用放大镜图标，或先点它再输入） |
| `Esc` | 在左栏搜索框里：清空并失焦；在顶栏搜索条里：收起搜索条；品牌菜单开着：收起并把焦点还给品牌区；帮助 / 关于对话框开着：由对话框自己关掉；导图 / 图表全屏时：退出全屏 |
| `Ctrl` + `P` | 打印 / 导出 PDF |

菜单与对话框开着的时候，`[` `]` `/` 这些全局快捷键**不会作用到背后的页面**（`Ctrl+P` 照常，打印的是整页）。

品牌菜单可以完全用键盘走：品牌区拿焦点后 `Enter`（或 `Space`）展开并自动进到第一项，
`↑` `↓` 在两项之间来回（到端点折返）、`Home` / `End` 跳首尾、`Enter` 选中。

## 关于与帮助

点顶栏品牌区弹出的菜单里有两项，两个都是**原生 `<dialog>` 模态框**（`showModal()`）：
打开时焦点锁在框内、背后页面变暗，`[` `]` `/` 一律不作用到背后，关掉后焦点回到原处。

**帮助**面板讲的是这一页的浓缩版：三栏与顶栏每个按钮、快捷键表、正文宽度怎么拖、全文搜索怎么用、
两种打开方式差别在哪。它是**内置在页面模板里**的（`page.template.html` 的 `#helpDialog`），
不去读 `docs/指南/界面与快捷键.md`——因为 `--serve <别的目录>` 能把浏览器指到任意文档目录，
那时候这篇文档根本不在。要改帮助文字，就改模板里那一段。

**关于…** 面板显示四行：软件名（取 `config.json` 的 `title`，与顶栏标题同源）、软件名称、版本、提交标记。
后三项来自构建时注入页面的 `<script id="build-info" type="application/json">`，值取自工程根目录的 `VERSION` 文件：

```
1.0.3+20a7f73
```

单行，`package.json` 的 `version` + `+` + 一个提交短哈希（`+` 是 semver 的 build metadata 分隔符，合法且一眼能拆）。
刷新它有两种方式：`node build-docs.mjs --stamp-version` 手写一次，
或 `node build-docs.mjs --install-hook` 装一个 `pre-commit` 钩子，让每次提交自动刷、并把 `VERSION` 一起加进这次提交。

三件事值得知道：

- **提交标记恒比当前提交落后一次**。pre-commit 跑的时候新提交的哈希还不存在，
  `git rev-parse --short HEAD` 只能给到它的**父提交**。换来的是不改写历史、已推送的提交不受影响；
  要精确对上某一次提交，看那次提交里的 `VERSION` 内容即可。
- **`VERSION` 变了，产物就该判过期**。版本串是构建注入的一部分，`node build-docs.mjs --check`
  会因为它不一致而报「已过期」——这是故意的，重新跑一次 `node build-docs.mjs` 让页面显示新版本。
- **离线版不联网也能显示版本**。`file://` 下没有 `fetch`，关于框只认页面里那个注入块，
  所以 `--serve` 期间改 `VERSION` 不会立刻反映到页面上，得重新构建。

## 全文搜索

点顶栏的放大镜图标，会从顶栏**下面滑出一条单行搜索输入框**并自动拿到焦点。搜索条是从顶栏背后滑出的
（不会把顶栏顶走），展开时**两侧栏与正文一起下移让位**，收起时原样回来，所以它不会盖住任何内容的第一行。
输入框右侧只有两个按钮：

| 按钮（图标） | 作用 |
| --- | --- |
| ✕ 清除 | 清空输入内容，并去掉正文里已有的命中高亮（不跳走，焦点留在输入框） |
| 放大镜 搜索 | 打开搜索结果页（等同于回车），并把搜索条收回顶栏背后，把整屏让给结果 |

再点一次顶栏放大镜、或在输入框里按 `Esc`，搜索条收回去。

**开合记在浏览器历史里**（每条历史记录各存一份，存在 `history.state`，不进地址栏）：前进 / 后退回到哪一条，
就还原成你当初离开它时的样子。所以上面那条链路是一路收起的——提交搜索收起、点结果进文档仍然收起、
后退回来也还是收起；反过来，你在某一条页面上手动把搜索条留着，回到那一条它就还开着。

**搜索范围**是程序启动时导入的全部文档原文（`config.json` 里标了 `hidden` 的也照搜），不区分大小写。
匹配按**行**做，跨行的短语不算命中（输入框本身就是单行）。文首的 `refs:` 声明行会被跳过——
那些行本来就不进正文，搜到了也无处可跳。

**结果页渲染在正文区**，按文档分组，从上到下依次是：标题命中的文档、其余按导入顺序。
每条结果给出「所在章节 + 命中行号 + 命中行及其上下各一行的上下文」，命中处用底色标出；
单篇最多列 40 处、整页最多 400 处，超出时组内提示「这篇还有 N 处没有列出」，
并建议换个更长的关键词。

**左栏同时换成「命中文件导航」**（每篇一条：标题 + 处数 + 路径）。点一条把视口**滚动**到正文里对应的那一组
（平滑滚过去，系统开了「减弱动效」就直接落位），那一组会闪一下描边、导航项标为当前；
这一步不改变地址栏，仍停在结果页。
左栏本来是关着的（`sidebar.defaultOpen` 为 false）也会被临时借出来用一下，离开结果页自动还回去——
只在内存里改，不写进你的记忆布局；但你自己开合过左栏，就以你的为准，不再替你还原。

**点任意一条结果**会打开那篇文档、滚到那一处命中，并把正文里所有命中处标上底色（当前这条更重一些）。
这类链接是可以直接发给别人的（形如 `#p=文档&h=章节&q=关键词&k=第几处`）。两点限制值得知道：

- 命中落在**折叠起来的图表源码**里、或者落在被图替换掉的围栏里时，会退回按所在章节定位；
- `.mermaid` 这类**整篇画成图**的文档会出现在结果里，但点开只能打开文档，标着「图形文档 · 不定位」——
  画布上的文字是 SVG，不是可以高亮滚动的正文节点。

## 窄屏行为

窗口宽度小于 860px 时，两侧栏变成抽屉：默认都收起，点顶栏按钮滑出，
点空白遮罩或右上角 `✕` 收起。顶栏会隐藏副标题与路径以节省空间；
按钮本来就是纯图标，所以窄屏下**一个都不藏**（旧版靠隐藏「打印」「链接」腾地方）。
搜索条展开时占满整行宽度，抽屉与遮罩从它下面开始，不会被搜索条盖住。
正文宽度的感应条这时也收起（`.w-edge{display:none}`）——正文本来就贴到了屏幕两边，没有「向外拖」的余地；
拖出来的那个宽度值仍留在本地，回到宽屏接着用。

## 嵌入的 Mermaid 图表（mermaid 围栏）

正文里用信息串为 `mermaid` 的围栏写的图，右上角会有一条小工具栏：

| 操作 | 方式 |
| --- | --- |
| 看 / 改源码 | 点「源码」就地摊开，再点一次收起（语法错时会自动摊开） |
| 复制源码 | 点「复制」，贴到别处改；按钮会短暂变成「已复制」 |
| 导出 SVG | 点「SVG」，导出的是自包含文件（含当前主题配色与底色，单独打开也正常） |
| 全页面显示 | 点「全屏」：这张图铺满窗口，并**按比例放大到放得下的最大尺寸**（宽图顶满宽度、高图顶满高度，另一轴居中留白），页面滚动被锁住，再点一次或按 `Esc` 还原；切换文档会自动退出 |

整体关闭（围栏退回普通代码块）用 `mermaid.enabled`。各类版式的写法示例见 `docs/示例/Mermaid 图表.md`。

## 页面上的状态提示

- **左栏底部**：显示按 `config.json` 过滤后的「当前显示 N 篇」（被过滤时才出现）、
  被忽略的非 Markdown 文件数量，以及一行**数据来源**——「实时读取 docs/」还是「离线快照（时间）」；
- **左栏底部**还有一行快捷键提示（`[/]` 左右栏 · `/` 搜索 · `Esc` 清除 · `Ctrl+P` 打印）；
- **首页那行小字**同样写明当前是实时读取还是离线快照，避免把旧内容当成最新；
- 搜索时左栏顶部会显示「搜索结果 N 篇」，清空搜索框即回到目录。

快照是不是旧的不用猜：`node build-docs.mjs --check` 判断产物是否已过期（过期退出码为 1），
适合接在提交前检查里；不确定差在哪时用 `node test/why-stale.mjs` 会把差异逐条列出来。

## 侧栏开关的实现要点

侧栏收起用的是「左栏负外边距滑出、右栏收窄裁剪」两套做法，都是为了在**不重排正文**的前提下把空间收干净：

- 左栏：`margin-left: calc(-1 * var(--left-w))`，左向溢出不会产生横向滚动条；
- 右栏：`width` 收窄到 0 并自己裁剪，内层保持原宽，视觉上同样向右滑出；右栏的纵向滚动下沉到内层列表，
  避免滚动条裁掉固定宽度的内容。

动画首帧用 `html.preload` 关掉过渡，避免加载时侧栏"滑一下"。

## 正文宽度的实现要点

正文宽度只有一个来源：`.article{max-width:var(--content-w)}`，而 `main` 是 `justify-content:center` 的弹性容器。
所以「对称调整」不用去算两条边——改这一个变量，居中的正文自己往两边长。

- **感应条** `.w-edge` 是 `main` 里两个绝对定位的窄条，位置写成 `left:calc(50% - var(--content-w)/2)`（右条镜像用 `right`），
  于是它永远贴在正文边缘上，不需要 JS 量像素、也不跟着侧栏动画重算；
- 条子**从边缘向内长 21px**，落在正文自己的左右留白里。往外长会盖住侧栏的滚动条（细滚动条一共 10px，
  被压掉一半就抓不住了）；位置还套了一层 `max(0px, …)`：正文撑满可用宽度时条子收在 `main` 内侧，不会溢出到侧栏上；
- 那条 2px 亮线是 `.w-edge::before`，写成 `left:50%` + `translateX(-50%)` —— **居中在命中区正中**而不是贴某一侧，
  所以从正文里往外挪一点、或从留白里往正边走，都够得着；
- **拖动时两侧一起亮**：`body.w-dragging` 把两条线都点到 `.5`，手里那条再叠 `.w-holding` 提到 `.85`。
  两侧线位都由 `calc(50% - var(--content-w)/2)` 驱动，所以**两条亮线之间的间距就是当下正文宽度**，全程不用 JS 量像素。
  分级刻意不写在 `:hover` 上：拖到上限时指针会甩出 21px 的条子，靠 hover 的话手里那条会忽明忽暗；
- **拖动算法**是「指针所在处就是边缘」：宽度 = 指针到 `main` 中线的距离 × 2，左右两条共用这一条公式。
  按下时先记下指针与边缘之间那最多 21px 的偏差、拖动时补回去，所以抓在条子哪儿都不会一按就跳；
- **上下限**：下限 560px（再窄正文就要一行折两行），上限不给固定数字，就是两侧栏之间当下剩多少。
  窗口缩放、侧栏滑入滑出都由 `ResizeObserver` 观察 `main` 触发重裁，所以拖不出横向滚动条；
  `main` 的宽度只由两侧栏决定、与正文宽窄无关，观察它不会来回打架；
- **`reading.maxWidth` 因此退居默认值**：`applyConfig()` 每次重渲染都要跑（首页、结果页、导图、图表都跑），
  让它直接写 `--content-w` 会把用户拖出来的宽度顶掉，所以它只调 `cwApply()`，由后者决定用本地记住的值还是配置默认值；
- 拖动态给 `<body>` 挂 `w-dragging`：`cursor:col-resize` 与 `user-select:none` 都靠它维持——
  指针甩得比 21px 的条子快，光标只写在条子自身上会一闪一闪，选中也会一路跟着拖出正文。
  只在松手时写一次 `localStorage`。打印时感应条跟顶栏一起 `display:none`，纸面上只有正文。

## 全文搜索条的实现要点

搜索条 `.searchbar` 是 `position: fixed; top: 52px`，收起时 `transform: translateY(-100%)` 加 `opacity:0`
与 `pointer-events:none`。关键是它的 `z-index: 39` **低于**顶栏的 `40`：这样收起时它是藏在顶栏**背后**，
而不是停在视口上方可见的位置，也不需要给顶栏再加一层遮挡。

展开只是给 `<body>` 挂 `search-open`，遮挡高度统一走一个变量：`:root{--overlay-h:52px}`、
`body.search-open{--overlay-h:calc(52px + var(--searchbar-h))}`。两侧栏是 sticky，改它们的 `top` 就整体下移；
正文不是 sticky，靠 `body.search-open main{padding-top:var(--searchbar-h)}` 推下去（带过渡，跟滑动动画同步）。
**只让侧栏不让正文，就会出现「搜索条盖住第一行标题」**——这是这一版修掉的 bug。
窄屏的抽屉与遮罩同样读 `--overlay-h`；打印时搜索条与顶栏一起 `display:none`，
正文那份下推也得跟着收掉（`body.search-open main{padding-top:0}`），否则每页顶部多一条空白。

开合状态存在 `history.state`，不是 JS 里的一个全局布尔，也不写进地址栏：

- 存 `history.state` 就是**每条历史条目自带一份**，前进 / 后退回来时 `route()` 第一件事是 `syncBarWithEntry()`
  把它还原回去，不需要额外记「用户当初在这儿是开着还是关着」；
- 写进地址栏（`&b=1` 之类）会让可分享的链接多一个跟内容无关的参数，否掉；
- 点链接、改 `location.hash` 开出来的**新条目没有记录值**，这时沿用屏上现状并 `replaceState` 补记一次——
  所以从结果点进文档时搜索条保持收起，而不是被路由弹回来（旧写法是 `#p=&q=` 一律展开，与「状态跟着条目」恰好相反）；
- 只有 `setSearchBar()` 会写状态，展开 / 收起 / 提交 / `Esc` 全都经过它，状态不会和 class 走岔。
  `replaceState` 包了 `try/catch`：个别宿主（沙箱内嵌等）不让写，代价只是还原不了，跳转与搜索都照常。

左栏的「命中文件导航」有四个刻意的选择：

- 导航项用 `<button>` 而不是 `<a href>`：它只是把视口移到正文里对应的那一组，
  不该改 hash——一改就把结果页顶掉了，点完就回不来；
- 落点躲开顶栏与搜索条靠 `.sr-group{scroll-margin-top:calc(var(--overlay-h) + 12px)}`，
  不是在 JS 里量像素：搜索条收着还是展开着，`scrollIntoView` 自己就知道该停哪儿；
- 左栏关着时结果页把它**借**出来用（`borrowLeftPane()`），离开结果页由 `route()` 还回去。
  只改内存里的 `state.leftOpen`、不调 `saveLayout()`，用户的记忆布局不受影响；
  而 `setPane('left', …)` 会先把借用标记清掉——用户自己动手开合过，就以他的为准。
  没命中时不借，免得为一条提示把侧栏撑开。
- 只有这条导航是平滑滚动（`behavior:'smooth'`，`prefers-reduced-motion: reduce` 时退回即时）：
  结果页里正文已经渲染完、位置不再变，滚过去不会落偏。`jumpToMatch` 那两条保持即时——
  正文刚重建时 `.pop` 入场动画和异步出图都在改高度，平滑滚动会在半路重新找位、来回抖。

跳转落点（`jumpToMatch`）有两处不是想当然就能写对的：

- 候选高亮节点要先用 `offsetParent === null` 滤一遍——命中可能落在**折叠起来的图表源码**里，
  那种节点选不中滚不到，看着就像"点了没反应"；一处都看不见时直接返回 `false`，让上层退回按章节定位。
- 落点要**再对一次**：Mermaid 是异步画的，画完正文高度会变，第一次 `scrollIntoView` 的位置会被后面的
  布局推移掉，所以 `state.mgPromise` resolve 之后再滚一次（节点还在文档里才滚）。

## 导图全屏的实现要点

「全屏」不是 `requestFullscreen()`，而是给导图容器加 `.mm-full`：`position: fixed; inset: 0; z-index: 60`，
铺满整个浏览器窗口并盖住顶栏与两侧栏（顶栏 `40`、侧栏 `35`、窄屏遮罩 `30`，所以取 `60`）。
这样做的好处是 `file://` 下不需要用户手势授权，退出也不受浏览器自身全屏状态（`F11`）影响；
同时在根元素上挂 `mm-full-on` 锁住底层滚动，退出时不会"跳回顶部"。
切换后容器的尺寸变了，`fit()` 读的是 SVG 的 `getBoundingClientRect`，所以要在下一帧和稍后各重适配一次。
打印时 `.mm-full` 会退回普通文档流，否则 `fixed` 覆盖层会把内容裁在一页里。

## 图表全屏的实现要点

覆盖层那套与导图一样（`.mg-full` + 根元素上的 `mg-full-on` 锁滚动），区别在「图怎么变大」：
导图是画在 canvas 上的，进出全屏后要调 `fit()` 重适配；嵌入的 Mermaid 图是 SVG，纯 CSS 就够——
让 `.mg-body` / `.mg-host` 吃满窗口，再把 `svg` 撑成容器的 `100%×100%`，SVG 自带的 `viewBox` 与
`preserveAspectRatio="xMidYMid meet"` 会自己等比缩放到装得下为止，窗口缩放也不用再量一次。

两个坑都写在 `assets/viewer.css` 那一段的注释里：mermaid 的 `svg` **没有 intrinsic 宽高**，
只写 `max-width:none` 会退回替换元素默认的 `300×150`（图反而比文档视图里还小，这就是「全屏后图很小」的成因）；
而且它把 `max-width` 写在 `style` 内联属性上，不用 `!important` 压不住。
打印样式也要用 `!important` 把全屏那套尺寸压回去（`height:100%` 在静态文档流里会塌成 0）。
